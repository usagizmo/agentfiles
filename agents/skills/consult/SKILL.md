# 設計判断の突き合わせ

**判断主体は実行中のエージェント**。アドバイザー（別モデル）は検証者であって命令ではない。判定基準と規模の定義は `~/.agents/AGENTS.md`。技術的収束はアドバイザーへ、製品判断はユーザーへ。

## モード

| モード     | いつ                           | 出すもの                                                              | 終わり方                                                                                                                                                |
| ---------- | ------------------------------ | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 軽量       | 修正方針・短い技術的疑問       | 問い / 案 / 触るパス / 懸念（3〜6 行）                                | 統合して 5〜10 行で提示                                                                                                                                 |
| 深い・事前 | 中規模以上の着手前             | ゴール / 変えるファイル / 主要判断と理由 / 懸念                       | 呼ぶ側が固定済みと示していない製品判断は **ユーザーの GO** まで実装しない。固定済みの範囲では技術レビューとして完了してよい（第二の製品 GO は要らない） |
| ループ     | 中規模以上の diff を書き終えた | ゼロベースの理想形と現状の差（責務・API・データフロー・SSOT・エッジ） | 同じ agent と**双方の未解決が無くなるまで往復する**。GO は要らない                                                                                      |

## 手順

1. 自分の判断を書く（モードの「出すもの」）
2. プロンプトを `mktemp` のファイルへ書く（下記。書き方は `references/advisors.md`）
3. `CONSULT_BACKEND` を明示して `<skills root>/consult/scripts/consult-backend.sh start <prompt-file>` → `collect <run-dir>`（起動表・backend 切替は `references/advisors.md`）
4. 統合する。論点ごとに 一致 / 取り込み / 不採用（理由）/ ユーザー判断が要る点。複数アドバイザーなら出典タグを付す。矛盾したら自分が仲裁し、同じ要約を全員へ送る（相互には話させない）
5. ループなら往復する（下記）。軽量・事前はここで終える
6. `close <run-dir>`

事前の GO ゲートに載せるのは 仕様 / 変更対象 / 主要判断と理由 / スコープ外 / 検証 / アドバイザーとの一致・取り込み・不採用。Plan Mode がある harness はそれを使う。

指摘を実測で不採用にするときは、測った対象（ディレクトリ・生成物・時点）が指摘の対象と一致することを確かめる。ずれているなら測り直す。

## ループ

1. 指摘を 1 件ずつ精査し、採用したものを直す。承認済みの範囲内の技術修正は自律で直し、製品判断が変わるときだけユーザーに聞く
2. 採否と理由・問い・修正の要約を書き、`ask <run-dir> <prompt-file>` で同じ agent へ送り、`collect` する。agent は文脈を保っているので diff は取り直させる
3. 1 へ戻る

終了は、生きている agent 全員が rc=0 で「指摘なし」を返し、かつ自分に未解決の問いが無い巡。**採用 0 件で指摘が残る巡が 2 連続したらユーザーへ**（新しい根拠も修正も出ていない）。

`start` が失敗して run dir が無いとき、または生きている agent がゼロになったときは、自分の判断だけで 1 巡して終え、**未レビューとして報告する**（レビュー合格ではない）。

## プロンプト

```markdown
あなたは設計判断のレビュアーです。コードは変更せず分析と提案だけ返してください。

## 必読

- ~/.agents/AGENTS.md（設計原則・ボーイスカウトルール）

## 背景・要件

{...}

## レビュー対象

{事前: パス + 注目点。全文は貼らない}
{ループ: git status --short / git diff / git diff --cached / untracked の中身}

## 私の判断

{...}

## 観点

- 設計原則からの逸脱（ゼロベース一致・根本解決・互換 shim / deprecated / dead code の残存）
- SSOT 複製（test が production 形を手コピー・同一 helper の二重）、shape / 型 / mock / 生成物の drift
- 経緯コメント（「以前は〜だった」・Issue / PR 番号）
- バグ・エッジケース・軸の混在・より良い代替・隠れたトレードオフ

## 出力

重要度順「ファイル:行 / 問題 / 推奨修正」。なければ「指摘なし」のみ。nitpick 不要。
末尾: このまま進めてよい / 修正推奨 / 再考推奨（一言）。
```
