# 意図の確認

**要否と、要否・結果の残し方は `intent-record.md`**。ここは要ると決まった後の見せ方。起動元では分けない。

**実物を渡す**。API は署名そのもの、CLI は実際の出力、UI は触れる状態のもの。「〜を追加しました」という要約では意図とのずれが見えない。ずれていたら直して再提示する。直して再提示するときは `intent-record.md` の失効に従う。

**UI に静止画を使わない**。押した感触・遷移・pointer の down / up のような操作の質が写らず、そこにこそ意図が宿る。静止画はエージェントが自分で見た目を観測する手段であって、人への提示物ではない。起動しっぱなしにして、どこを触れば見えるかを添えて渡す（起動と後始末の条件は project の検証 skill）。

**項目ごとに分けて見せる**。まとめて「これでどうですか」と出すと返事も 1 つになり、どの項目が承認されたのかが残らない（数え方と沈黙の扱いは `intent-record.md`）。

**項目ごとに「いま待っている問い」へ書く**（質問の SSOT は `wait-record.md`）。

| 項目         | 書くもの                                        |
| ------------ | ----------------------------------------------- |
| 人が触れる   | 操作と、その結果として見えるもの                |
| 人が触れない | 操作できないことと、判断材料（policy / テスト） |

| 欄                 | 書くもの         |
| ------------------ | ---------------- |
| いま待っている問い | 上の表           |
| 見せたもの         | 何をどう見せたか |
| 項目ごとの状況     | 承認の進捗       |

```markdown
## いま待っている問い

- 保存を押す → 一覧に新しい行が見える
- 公開 API の型は操作できない。判断材料: 型定義と契約テスト

## 見せたもの

起動中の UI。変更後の公開 API の型定義。

## 項目ごとの状況

| 項目               | 状況 | 誰が何を承認したか |
| ------------------ | ---- | ------------------ |
| 保存して一覧に出る | 未   |                    |
| 公開 API の型      | 未   |                    |
```

**記録したあとに見せる。先に見せない**（順序は `intent-record.md`）。停止条件ではない。要るなら人待ちを `waiting` にする。
