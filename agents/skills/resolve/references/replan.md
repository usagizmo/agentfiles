# 再 plan

**時刻や「統合先が進んだ」では判定しない。内容で判定する**。そうしないと、無関係な進行のたびに計画を作り直すことになる。

**面をまたぐ path の突き合わせ方は `landing-surface.md`**（接頭辞の付いた scope を素の文字列一致で比べると、一度も交差せず失効しない）。ここに写さない。

| 起きたこと                                                                                | 対応                                                                                                               |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Issue 本文が変わった                                                                      | **停止して再承認を待ち**、承認後に再 plan（停止条件は `../SKILL.md`）                                              |
| 依存先の merge SHA が変わった                                                             | 再 plan                                                                                                            |
| **どれかの面で base から統合先までが** `invalidationScope` か同じ `resourceKeys` に触れた | 再 plan                                                                                                            |
| 実装中に前提誤り・未宣言の資源が判明した                                                  | 再 plan                                                                                                            |
| どの面も無関係な場所だけ進んだ                                                            | **rebase のみ**。計画は再利用する                                                                                  |
| **提出前に宣言を実体へ狭めた**                                                            | **再 plan ではない**。base も動かさない（手順は `../SKILL.md`）                                                    |
| **自分がその面へ着地した**                                                                | **再 plan ではない**。**その面の base だけ新しい統合先へ更新する**（自分の commit を自分への失効として読ませない） |

**再 plan では最初に、全着地面の base を今の統合先へ更新する**（制御面は `baseSha`、他の面は `landingBaseShas` の各キー）。外から失効を判定する側は**交差が消えたことでしか収束を知れない**ので、後回しにすると同じ失効通知が届き続ける。Issue 本文の変更で作り直したときは `issueDigests` も同じコメント内で更新する。

**1 面でも更新し漏らすと収束しない。**判定は面ごとに独立なので、残った面の交差が毎 tick 真のまま当たり、伝える側の失敗が積まれて `退避先` へ落ちる**。制御面は着地面に含まれなくても更新する** —— project 差分と共有ファイルはそこにあり、どの課題もそれを読んで計画を立てている。
