# 状況ボード

**`conductor` が更新し続ける Artifact 1 枚が、盤面の現在地**。ここを読んで人の問いに答える。
**何を載せるかの SSOT は `conductor` の「状況ボード」の節**で、ここには写さない
（行を足すたびに 2 箇所直すことになり、写した側が落ちた行に黙って追随しなくなる）。

## 引き当てる

**題名を固定して一覧から引き当てる。URL は記憶しない**。記憶に置くと、作り直された版を
見失って古い方を読み続ける（向こうが更新に使う規律と同じ）。

**書き換えない**。向こうの出力なので、直しても次の tick で上書きされ、
**人はどちらを読んでいるか分からなくなる。**

## 読む

**ボードが載せているのは向こうの判断**であって状態そのものではない。
生の Issue や git からは出てこない（なぜその action を選んだか、何を待っているか、規約を曲げたか）。

**全件を raw から組み立て直さない**。盤面の把握は 1 課題あたり複数の API 呼び出しになるので、
**最初から raw で組むと、聞かれたことに答えるより先に時間と context を使い切る。**
ボードで当たりを付け、**答えに効く事実だけ**観測し直す。

**ボードが古いなら、まずそう言う**。黙って raw から組み直すと、高くつくうえに
**ボードが機能していないことが人に伝わらない**（それ自体が報告すべき異常）。

**聞かれたことにだけ答えない**。ボードが人へ返しているもの（詰まり・`退避先` の滞留・
着地の積み残し）は、**誰も見に来ないことで死ぬ**。聞かれていなくても一緒に出す。
**項目を列挙しない** —— 増えた行に黙って追随しなくなる。
