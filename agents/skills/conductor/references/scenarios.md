# 代表シナリオ

**tick の意味論を固定する表**。観測 → 正規化 → 選ぶ action を、実際に起きる状況で書き下す。

本文の節を動かす・条件を書き換えるときは、**この表の期待 action が変わらないことを先に確かめる**。変わるなら意味論を変えている。行数が減ったことは正しさの証拠にならない — 事故を防いでいた条件が 1 つ消えても、静的な検査（参照・層・重複）は通る。

**射程は tick の意味論を決める節すべて** —— 正規化・action の優先順とその条件・資源の保持と回収・入場を止める宣言・先発後発の順序・既定値。**action の入力（誰が何を保持しているか）を変える編集も含む** —— そこは期待 action としては薄くしか現れないので、`tick.md` と `resources.md` の論証も併せて読む。

**各行は「他の上位 action の条件は成立していない」ことを前提にする**。そうでないと上位が勝つ。期待 action は本文「action の優先順」の名前で書く（番号は増減する）。

## 使い方

1. 変更前にこの表の期待 action を確認する
2. 変更後、各行の観測から本文だけを読んで同じ action に辿り着けるか確かめる（**action の選定は本文、選んだ後の手順は `protocols.md`**）
3. 辿り着けない行が出たら、**その行が指す条件が本文から消えている**。戻すか、表を意図的に更新する
