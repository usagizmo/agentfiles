# 代表シナリオ

**tick の意味論を固定する表**。観測 → 正規化 → 選ぶ action を、実際に起きる状況で書き下す。

本文の節を動かす・条件を書き換えるときは、**この表の期待が変わらないことを先に確かめる**。変わるなら意味論を変えている。行数が減ったことは正しさの証拠にならない — 事故を防いでいた条件が 1 つ消えても、静的な検査（参照・層・重複）は通る。

**射程は tick の意味論を決める節すべて** —— 正規化・action の優先順とその条件・資源の保持と回収・入場を止める宣言・先発後発の順序・既定値・**いつ打つか**（次の tick が始まる条件なので、意味論の外側ではない）。**action の入力（誰が何を保持しているか）を変える編集も含む** —— そこは期待としては薄くしか現れないので、`tick.md` と `resources.md` の論証も併せて読む。

**各行は「他の上位 action の条件は成立していない」ことを前提にする**。そうでないと上位が勝つ。期待欄の書き方は下の「期待欄の形」。

## 期待欄の形

**期待欄が取りうる形は 3 つで、これで閉じている**。先頭トークン 1 つが主命題。直後の括弧は主命題のパラメータ（差し戻しの戻し先・渡す資源・足りない前提）を運び、そこから後ろの散文は根拠・例外・他の主体の扱いを書く副節。

| 形            | 先頭トークン                       | 使ってよい条件                              |
| ------------- | ---------------------------------- | ------------------------------------------- |
| **遷移**      | action 名そのまま / `何も選ばない` | 既定。候補に残る action が 1 つ             |
| **制約**      | `制約（<下位分類>）`               | 観測だけでは候補が 2 つ以上に割れるときだけ |
| **action 外** | `action 外（<下位分類>）`          | tick の action 選定という軸に乗らないもの   |

**action 名の SSOT は本文「action の優先順」**。ここには写さない。`何も選ばない` は選択結果の null 値で、action 名の集合には混ぜない。**番号では表も行も決まらない** —— 行 ID と action 番号は同じ字面を持ち（`10c` は両方に在る）、しかも action 番号は増減する。

下位分類も閉じている。

| 形        | 下位分類                  | 固定するもの                                    |
| --------- | ------------------------- | ----------------------------------------------- |
| 制約      | 選ばれない action         | その action を選ばないこと                      |
| 制約      | 受け手・候補の資格        | 枠の受け手・claim の候補になるか                |
| 制約      | 資源境界                  | どの資源を保持したままか                        |
| 制約      | 手段の不在                | conductor 側にその操作が無いこと                |
| action 外 | 起床                      | 次の tick が始まるかどうか                      |
| action 外 | 人から渡されたものの処理  | action にも上限にも数えない処理                 |
| action 外 | action の選択と独立な精算 | 記録の更新だけで、action を選ぶ軸に乗らないもの |

**強度順を守る。遷移が書ける行を制約で書かない** —— 制約は「選ばれない」しか固定しないので、遷移で書ける行を落とすと回帰表がそのぶん薄くなる。楽な「〜しない」へ寄せていくと、静かに何も守らなくなる。

**分かれ目は、候補に残る action が 1 つか複数か**。1 つなら、その action 自身の前提が観測に書かれていなくても括弧で足して遷移で書く（`**枠を渡す**（資源キーが交差しなければ）`）。**制約へ落とすのは、観測だけでは候補が 2 つ以上に割れるときだけ** —— そこで 1 つに決めると、書いていない観測を固定することになる。

**制約の副節を `通常どおり` だけで済ませない**。どの条件を無効にするのかまで書く（無効にする対象が無いなら、それは制約ではなく遷移で書ける行）。先頭トークンの側は下の 4 つめのコマンドが落とすが、副節は機械では見ない。

**2 つ以上の主体が登場する行では、期待がどの主体についてかを書く**。期待欄でも観測欄でもよい。

**節の全行が同じ形なら、節冒頭で宣言して行ごとの前置を省いてよい**。宣言は行頭から `**この節は全行が <形>（<下位分類>）**` の字面で書く（`<形>` は `制約` か `action 外`） —— 検査はこの字面で節を飛ばすので、言い回しを変えると免除が黙って外れる。当たるのは起床節だけ。

## 行 ID

**`<数字><添字>` の識別子**。行の位置でも順序でもないので、表の中からも別 file からもこれで指せる（`17l` → `17k` のような相互参照が実在する）。

- **同じ ID を持つ行を file 内に 2 つ作らない**
- **1 つの数字部分を、2 つの節が共有しない**。添字は節ごとに独立に振るので、数字を共有した時点で次に足す行が衝突する —— 片方の節が `a` を、もう片方が `b` を使って分け合う形は、ID としては一意でも原因が残ったまま。**1 つの節が複数の数字を持つのは可**（下位トピックの並びを数字で表している節がある）
- **その帯の最初の行は素の数字か `a`**。素の数字で始めたなら次の添字は `b` から。新しいトピックなら次の文字、既存行の派生なら親の ID + 連番（`17c` の派生が `17c2`、`8b` の派生が `8b2` / `8b3`）
- **欠番は埋めない**。新しいトピックはその数字で使われている最大の**文字**の次へ、派生はその親で使われている最大の連番の次へ足す。**例外だった数字 `8` は解消済み** —— 退役していた `e`〜`m2` を跨いで `8n` まで進めたので、以後は通常どおり最大の文字の次（`8o`）
- **削除した ID を再利用しない**。commit message・Issue コメント・状況ボードに書かれた ID は消せないので、再利用すると過去の参照が黙って別の行を指す。退役は file から観測できないため、歯止めは 1 つ上の 2 つ（欠番を埋めない規約と、それが破れる数字にだけ置く例外注記）だけ
- **一意性と数字帯を保つため以外の理由で振り直さない**（見た目を揃える・番号を詰める）。振り直しも過去の参照を別の行へ向ける操作なので、払う理由があるのはその 2 つだけ
- **隣接に依存して指さない**（「同じ形だが」だけで直前の行を指す）。行は動くので、指すなら **`行 <ID>` と書く** —— 素の数字の ID は本文の数量と字面が同じなので、印が無いと機械で拾えない

| 12b | 先に計画済みだった側の本文が相互記載で動き、**書き換えた側が相手の `ready` も upsert 済み** | **何も選ばない**。digest は合っている。upsert し損ねた側は digest が合わなくなるので、在庫の陳腐化が拾う                                                                                                                                                                                                                 |
| 12c | 別々の計画セッションが走っている 2 件が、同じ group に属すると判明した                      | **何も選ばない**。conductor には止める action が無い（止めると外部化されていない計画が消える）。書く側が譲る —— 生きた計画セッションが持つ本文は触らず、自分の本文にだけ宣言を書く（`same-branch.md`「他人の本文を触ってよいか」）                                                                                       |
| 12d | conductor がこの tick で規約の穴を見つけた                                                  | **規約の穴を起票する**。同じ action の中で `Backlog` の最上段まで置く。文書の課題の順序は規約が決めているので人を待たない —— 末尾のままだと、後続の全セッションが古い前提のまま走る                                                                                                                                      |
| 12e | 人が「#N を `Backlog` 最上段へ」と指示した                                                  | **action 外（人から渡されたものの処理）** —— 並べ替えを実行する。action にも上限にも数えない。手段は `intake.md`                                                                                                                                                                                                         |
| 12f | 計画済みの group で、**代表は鮮度が生きていて、別の成員だけ在庫の鮮度が失効している**       | **差し戻す**（→ 未計画）。戻すのは古くなった成員だけ。鮮度の記録は成員ごとに書かれるので、group へ畳むと古くなっていない成員まで戻る（この事象だけ戻す単位が Issue）                                                                                                                                                     |
| 12g | claim 済み group の**非代表成員**を正規化する                                               | **何も選ばない**（その成員について）。共有する実体は代表の番号で 1 セットなので、成員ごとに自分の番号で引くと全員が `未着手` に落ち、claim するたびに `ledger が期待より先` になる                                                                                                                                       |
| 12h | 行 12g の group が着地した                                                                  | **成員も `着地済み`**。共有を反映しないと、代表だけが終端に達して「終端の混在」になる                                                                                                                                                                                                                                    |
| 12i | claim の記録の `members` にだけ居る番号（本文に宣言が無い）                                 | **同じ対象集合として扱う**。加入は記録への追記が実体で、本文の宣言を待た**ない**                                                                                                                                                                                                                                         |
| 12j | claim 前の group で、成員の側にだけ人待ちの記録がある                                       | **その成員は `人待ち`**。共有を当てるのは claim 済みのときだけ —— claim 前は代表が決まっておらず、人待ちは渡された Issue に書かれる                                                                                                                                                                                      |
| 12k | 片方向の `Same branch as` で、**書いていない側が board 上で先に来る**                       | **1 つの group として扱う**。宣言は片方向でも成立する —— 有向辺のまま辿ると並び順で連結成分が割れ、1 本で直すための宣言が 2 本の branch を生む                                                                                                                                                                           |
| 12l | claim 済み。wait は成員にだけあり、代表のセッションは `blocked`                             | **報告して止める**（Conflict / 証跡が矛盾している）。claim 後の wait は代表のコメントだけを読む。成員の記録は runtime に写さない。消さない                                                                                                                                                                               |

## 起床

**この節は全行が action 外（起床）**。決めるのは「次の tick がいつ始まるか」で、正規化の 4 フィールドを通らない。節冒頭のこの宣言で行ごとの前置に代えるので、期待は起床の有無と、起床に代えて行う操作で書く。

| #   | 観測                                                                                             | 期待                                                                                                                                                                                                   |
| --- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 16  | tick が観測して action を実行せずに終えた。**その直後**に実行器が `working` から `done` へ落ちた | **次のラウンドで起きる**（fallback を待たない）。baseline は tick が読んだ観測なので、この遷移は差分に出る。**遷移の列挙で塞いでいない** —— 同じ隙間に入る人待ちの記録・Status の変更・PR の作成も同じ |
| 16b | 行 16 と同じ tick の直後、外の状態が何も動かない                                                 | **起きない**。渡した baseline と現状が一致する。自分の action 由来の起床もここには無い（何も実行していない）                                                                                           |
| 16c | tick が **action 上限**で終えた                                                                  | **起きる**。baseline は最後に実行した action の入力なので、その結果が差分に出る。続きがあるので正しい起床                                                                                              |
| 16f | action は 0 件だが、周回か失敗の記録の `count` を精算して**書いた**                              | **起きない**。書いたら上限に数えないまま観測からやり直すので、渡す baseline は自分の書き込みより後になる。やり直さないと、何も実行していない tick が自分のコメント 1 行だけで起こされる                |
| 16d | tick の観測そのものが失敗した                                                                    | **直前に成功した snapshot を渡して張る**（+ 報告）。**張らない側へ倒さない** —— watcher は tick の終わりに 1 本だけ張るので、張らずに終えると起こし手が消え、一時的な API 障害が永久停止に化ける       |
| 16g | 起動直後の最初の tick で観測に失敗した（成功した snapshot が 1 つも無い）                        | **報告して止める**。渡せる baseline が存在しない。**取り直して張らない** —— 取り直した時点が baseline になって窓ができる。人が起こす                                                                   |
| 16e | 渡した baseline の file が消えている / 空                                                        | **起動を止める**（状況ボードの「制約・異常」へ）。自分で取り直す側へ倒さない —— 倒すと窓が黙って戻り、しかも戻ったことを誰も観測できない                                                               |

## 使い方

1. 変更前にこの表の期待を確認する
2. 変更後、各行の観測から本文だけを読んで同じ結論に着けるか確かめる。**照合の相手は形で決まる**（**action の選定は本文、選んだ後の手順は `protocols.md`**）

   | 形        | 何と照合するか                                                                                          |
   | --------- | ------------------------------------------------------------------------------------------------------- |
   | 遷移      | 本文から選ばれる action が先頭トークンと一致するか。`何も選ばない` はどの action の条件も成立しないこと |
   | 制約      | 上の下位分類の表の`固定するもの`が、本文から出るか                                                      |
   | action 外 | 同じく`固定するもの`が本文から出るか（その軸に乗るなら遷移か制約で書ける行）                            |

   **括弧も照合する** —— 戻し先と渡す資源は主命題のパラメータなので、名前が合っていても中身が違えば不一致。足りない前提を書いた括弧は、その前提を仮定して照合する。

   **機械で落とせるのは先頭トークンの字面まで**（下の 4 つめのコマンド）。同じ結論に着けるかは意味の照合なので、ここで人が確かめる領域のまま残る。

3. 辿り着けない行が出たら、**その行が指す条件が本文から消えている**。戻すか、表を意図的に更新する
4. **行を足した・消した・別の節へ移した、節を足した、ID・観測・期待のどれかの欄を触った、本文の「action の優先順」の名前を変えたら、下の 6 つを確かめる**（最後のひとつは 4 つめのコマンドがその表を入力にするため）。「行 ID」の規約だけでは重複を検出できない。

| 見るもの           | 引き方                                                                                  |
| ------------------ | --------------------------------------------------------------------------------------- |
| 行とテストの対応   | `bun test test/scenarios.test.ts` が通る（**移していない行はもう無い**）                |
| ID の重複          | 下の 1 つめのコマンドが何も出さない                                                     |
| 数字部分の節またぎ | 下の 2 つめのコマンドが何も出さない                                                     |
| 相互参照           | 下の 3 つめのコマンドが何も出さない                                                     |
| 期待欄の形         | 下の 4 つめのコマンドが何も出さない（先頭トークンだけを見る）                           |
| action の指し方    | 副節でも action を番号で指していない（「期待欄の形」のとおり名前で書く）                |
| 退役した添字       | 消した・移した結果その帯の最大の文字か連番が下がったなら、退役した範囲が「行 ID」に在る |

```bash
# この file のあるディレクトリで実行する

# 重複した ID
awk '/^\| [0-9]/ {split($0, a, "|"); id = a[2]; gsub(/ /, "", id); print id}' scenarios.md |
  sort | uniq -d

# 数字部分を共有している節
awk '/^## / {s = $0}
     /^\| [0-9]/ {split($0, a, "|"); id = a[2]; gsub(/ /, "", id); sub(/[a-z].*$/, "", id); print id "\t" s}' scenarios.md |
  sort -u | cut -f1 | uniq -d

# 実在しない行を指す `行 <ID>` の参照
comm -13 \
  <(awk '/^\| [0-9]/ {split($0, a, "|"); id = a[2]; gsub(/ /, "", id); print id}' scenarios.md | sort -u) \
  <(grep -oE '行 [0-9]+[a-z]?[0-9]?' scenarios.md | cut -d' ' -f2 | sort -u)

# 閉集合に無い先頭トークン（遷移は SKILL.md、制約と action 外は上の下位分類の表から引く）
awk '
  BEGIN { ok["何も選ばない"] = 1 }
  FILENAME ~ /SKILL\.md$/ {
    if (/^### /) s = ($0 == "### action の優先順")
    if (s && /^\| /) { split($0, a, "|")
      if (match(a[3], /\*\*[^*]+\*\*/)) ok[substr(a[3], RSTART + 2, RLENGTH - 4)] = 1 }
    next
  }
  /^\| (制約|action 外) +\| / { split($0, a, "|"); f = a[2]; d = a[3]
    gsub(/^ +| +$/, "", f); gsub(/^ +| +$/, "", d); ok[f "（" d "）"] = 1 }
  /^## / { skip = 0 }
  /^\*\*この節は全行が (制約|action 外)/ { skip = 1 }
  !skip && /^\| [0-9]/ {
    n = split($0, a, "|"); id = a[2]; gsub(/ /, "", id); c = a[n - 1]; sub(/^ +/, "", c)
    t = match(c, /^\*\*[^*]+\*\*/) ? substr(c, 3, RLENGTH - 4) : "(先頭が強調でない)"
    if (!(t in ok)) print id "\t" t
  }
' ../SKILL.md scenarios.md
```
