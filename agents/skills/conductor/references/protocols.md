# 選んだ後の手順

tick の分岐そのものではなく、**その action を選んだ後に何をどう書くか**。選ぶ条件は `src/decide.ts` の `LADDER`。

**marker は前後に何も無い 1 行として置く**。読む側はその形だけを記録として引く（`src/records.ts` の `standaloneLines`）。行の途中や code span の中に書いた字面は記録に数え**ない**ので、まとめや経緯のコメントで marker に言及してよい。

## claim する

**remote branch の一意作成が二重着手の最後の防壁**なので、順序を守る。

1. Issue 契約を検証する（group なら全員分）
2. **着地面を解決する**（本文の宣言 → 座標表。解決できなければ候補を捨てて次へ。`landing-surface.md`）
3. **制御面の** remote branch を代表の番号で一意に作成する。失敗したら候補を捨てて次へ
4. **claim の記録を代表の Issue へ書く**（代表と全員の番号、および解決した着地面。形式は `same-branch.md`）
5. **記録した全員**の Status を進行中にし、assignee を自分にする（group でも代表だけにしない）
6. **着地面ごとに** branch と worktree を作る（同じ branch 名。その時点の統合先から切る）
7. セッションを起こす（`harness.md`）

- **4 が書けなければ、3 で作った remote branch を消してから終える**。branch を作るのは記録を書く直前で、書けたことを確かめるまでが 1 手
- **5 が誰か 1 人でも失敗したらセッションを起こさない**。branch は残し、次の tick へ返す
- **Project の更新失敗で claim をロールバックしない**。branch が真実で、Status は台帳
- **base は常にその面の統合先から切る**（制御面では default branch）。他 branch から切ら**ない**
- **着地面を解決してから branch を作る**（順序を逆にすると、座標表に無い面の claim branch だけが残る）

**branch を新しく作ってよいのは、その面に branch が無いときだけ**（claim の初回と、部分 claim で欠けた面を埋めるとき）。**在る branch は上書きしない**。起こし直しで worktree を作り直すときも同じ述語で、在れば checkout、無ければ統合先から作る。**「claim の 1 回だけ」と読まない。**

## 失敗の記録

**retry budget をセッションの記憶に置かない**。Issue コメントへ固定 marker で外部化し、正規化と起床 snapshot の入力に含める。

````markdown
<!-- retry -->

```yaml
count: <連続失敗回数>
lastAction: <失敗した action の名前>
```

<!-- /retry -->
````

同じコメントを書き換える（`count` を +1 して upsert する。**コメントを増やさない**）。何を数え、何を数えず、いつリセットするかは本文「1 tick」が SSOT。ここは書式だけ。

## 周回の記録

**実行器を 1 周回して何も出なかった周**を数える。失敗の記録とは**別の marker にする**（あちらは操作の失敗、こちらは成功した周の空振り）。

````markdown
<!-- cycle -->

```yaml
mark: <成果の指紋>
count: <成果ゼロで回った周の数>
```

<!-- /cycle -->
````

同じコメントを書き換える（増やさない）。帰属は `same-branch.md`。当たる action は Decision の `countsEmptyCycle`。上限は本文「硬い上限」。

**返った Decision に対して書く**。値は `records` が持つ。`observeTick` を再実行せず、`cycle-mark.py` を手で組まない。

1. `markMatch` が `changed` なら、実行の前に `count` を 0 にして `mark` を `currentMark` へ更新する。`unknown` では照合を飛ばす
2. action を実行する
3. **`same` で、回すことに成功し、かつ `countsEmptyCycle` が真の周の後でだけ** `count` を +1 する

- **`mark` を新しく書いた周は加算しない**（前の周に成果があった、または初回という意味）
- **3 を回す前に置かない**（更新してから dispatch までに落ちると tick が冪等でなくなる）
- **回せなかった周はここで数えない**。それは操作の失敗なので失敗の記録が数える

### 指紋は `scripts/cycle-mark.py` が作る

**この実装が符号化の SSOT**。成分の名前・順序・区切り・長さの数え方・出力表現・git の取り方はすべてそこにある。**ここへ同等物を書き写さない。**

- **手で連結しない**。同じ観測から必ず同じ値になることが、action が一意に決まる条件
- **python3 が要る**。持てない環境ではその tick は照合へ到達しない。**散文から手計算を再発明しない**
- 渡すのは conductor が既に正規化している値だけ。**曖昧さを引数境界へ移さない**

| 引数                                                 | 中身                                                                          |
| ---------------------------------------------------- | ----------------------------------------------------------------------------- |
| `--ledger <値>`                                      | **どちらの式を使うかを決める**（`未計画` なら計画の周、他は解決）             |
| `--progress <値>`                                    | 解決の周のみ                                                                  |
| `--landing <repo>:<path>`                            | 解決の周のみ。**着地面ごとに 1 つ**（面の名前と checkout path）               |
| `--host <host>`                                      | 解決の周のみ。全着地面の remote が在るべき host（制御面の origin から取る）   |
| `--branch <repo>:<名前>` \| `--no-branch <repo>`     | 解決の周のみ。**着地面ごとにどちらかを 1 回**（ローカル branch も解決する）   |
| `--worktree <repo>:<path>` \| `--no-worktree <repo>` | 解決の周のみ。**着地面ごとにどちらかを 1 回**（省いた面は成果が指紋に出ない） |
| `--plan-comment <file>` \| `--no-plan-comment`       | 解決の周のみ。file の bytes は下表                                            |
| `--wait-record <file>` \| `--no-wait-record`         | **有効なときだけ file を渡す**（有効の判定は `wait-record.md`）               |
| `--issue-body <番号>:<file>`                         | 計画の周のみ。対象集合の全件（並べ替えは実装が行う）                          |

**file の bytes**は次の値そのもの。足しも落としもしない。

| 引数             | bytes                                                                                     |
| ---------------- | ----------------------------------------------------------------------------------------- |
| `--issue-body`   | Issues API の JSON `body` を parse した文字列の UTF-8。取り方は `body-digest.md`          |
| `--plan-comment` | `extractMarker` へ `plan` を渡して `present` のときその値。それ以外は `--no-plan-comment` |
| `--wait-record`  | 有効なときだけ `extractMarker` へ `wait` を渡して得た値。それ以外は `--no-wait-record`    |

抽出の手順は写さない。`--issue-body` に digest は書かない。

- 式を `ledger` で決めるのは、action 名では切れないから（照合は action を選ぶ前に走る）
- **着地面を 1 つでも落とさない**（落とした面の成果は指紋に出ない）
- **「無い」は明示して渡す**。省略は usage error で、指紋は返らない
- **照合できない周でも action の選択は続ける**。飛ばすのは照合だけ

検査は `scripts/cycle-mark.test.py`。**符号化を変えたら通してから使う。**

### 何を成果と見なすか

**成果物の側だけから作る**。成分の集合と符号化は `scripts/cycle-mark.py` が持つ。

- **`runtime` とセッションの状態は入れない。commit 数でも引かない**（理由は `tick.md`）
- **変わったかどうかの判定は git に任せる**
- **中身まで入れる**。真偽値への丸めも不可
- **git が見える未コミット状態を、置き場所を問わず入れる**。ignore 対象と git の外は入れない
- **stash の帰属を subject から推論しない**。リスト全体を、着地面の checkout（共通 dir）から取る
- **`progress` と人待ちの記録を入れる**
- **無効な人待ちの記録を数に入れない**
- **着地面ごとの成分は面の名前と組にする**
- **branch も worktree も無い段階でも作れる**（claim 前・checkout を作る前・終端で実体を消した後）。**段階で免除を分けない**

### 見えないもの

**成果物が動いても指紋に出ない経路がある。`退避先` へ落ちた課題では、まずここを疑う。**

- `skip-worktree` / `assume-unchanged` を立てた path —— git 自身が変化を見ない
- untracked な nested repository の中身 —— git が 1 件に畳むので、出現と消滅は見えるが中の commit と編集は見えない
- 観測の途中で書かれた成果 —— 成分は別々の時点で撮る。**commit だけは前後で HEAD を撮って閉じてある**が、index と worktree の残りは開いたまま
- `git stash create` —— `refs/stash` を更新しない。既知の穴であって塞ぐ対象ではない

**tracked な submodule だけは畳まずに落ちる**（指している commit が動いた周と動いていない周が同じ値になるため、符号化を決めるまでは観測の失敗にしてある）。

- **落ちるのは変化が観測されたときだけ**。clean な submodule では止まらない
- **untracked の nested repository を同じ扱いにしない**（あちらは課題の成果物ではない外部の物体）

**`mark` が無いときは壊れた記録にしない**。現在の指紋を書いて `count` を 0 にする（初回の周がここ）。

**符号化を変えたら旧 `mark` は捨てる**。変換も新旧の併用もし**ない**。全件が 1 度だけ不一致になって `count` が 0 に戻る。

## 休止の記録

後発に休止を伝えたことを外部化する。conductor が書き、conductor が消す。消すのは「失効した記録を片付ける」と「枠を渡す」。retry の解除は本文「記録の精算」。ここは書式と伝える順だけ。

````markdown
<!-- yield -->

```yaml
issues: [<Issue 番号>] # 対象集合の全番号
to: <先発の Issue 番号>
keys: [<交差した資源キー>]
```

<!-- /yield -->
````

同じコメントを書き換える（増やさない）。`runtime` への写り方は本文「正規化」が SSOT。

先に伝えてから書く。書けなければ次の tick で同じ action が再送する。書いてから伝え**ない**。

## 計画セッションを片付ける

手順は `harness.md` の `refine` 行。述語は本文「計画セッションの rename」。閉じる / rename の手順はここへ書かない。

## 片付ける

**所有していないものは消さない**。手順は `harness.md`。`resolve` は**全着地面の worktree**を片付ける。

**途中で止まっても、台帳の `完了` から再開できる**。面ごとに消すので、4 で先に `完了` を書き、片付ける action はそこも入口にする。**記録を消すのは実体を消し終えてから。**

列は入口で引く。`progress` が `着地済み` / `取り下げ` ならその列。`ledger` が `完了` で入った片付けと、PR が `merged` で claim の remote branch が無い片付けも `着地済み` の列を使う。

| `progress` | 消すもの                                                                                                    | 残すもの                      |
| ---------- | ----------------------------------------------------------------------------------------------------------- | ----------------------------- |
| `着地済み` | 全着地面の worktree・セッション・**merge 済みの** branch・制御面の claim branch・claim の記録・その他の記録 | **merge されていない branch** |
| `取り下げ` | worktree・セッション・記録                                                                                  | **branch と claim の記録**    |

- **merge されていない branch を消さない**。PR を使わない面の着地は commit までなので、統合先への merge がまだでも `着地済み` になる。人が merge するまで branch を置き、worktree だけ返す
- **1 面でも残したら片付いていない**（実 checkout が残る。`progress` は終端なので二度と拾われない）
- **あわせて制御面の claim branch を消す**（着地面に制御面が含まれるかに依らず）。claim の防壁は常に制御面の remote branch
- **live checkout は片付けの対象ではない**（`landing-surface.md`）

### 片付ける前に成果を確認する

**worktree とセッションを消すと、セッションまとめが一緒に消える**。着地の確認と片付けを続けて実行しない。

1. **セッションまとめの記録があるか確認し、`積み残し・懸念` を人へ渡す**。**固定 marker で引く**（提出のものと止まったもののどちらでもよい。形式は `session-report.md`）
2. 載っていなければ pane から回収する。pane も消えていれば harness の transcript を探す
3. **どこにも無ければ片付けず報告する**。消えたものは復元できない
   - **例外は** PR が `merged` で claim の remote branch が無いとき。まとめが無くても片付ける
4. **着地済みの列なら、実体を消す前に台帳を `完了` へ寄せる**。**取り下げの列では台帳を触らない**
5. **着地済みの列で Issue がまだ open なら close する**。1〜3 を通ってからでないと閉じ**ない**
   - **面の構成で分岐しない**（0 commit で透過した面では PR が存在しない）。既に closed なら何もしない
   - **取り下げの列では閉じない**（Issue を開けておくかどうかが製品判断）
6. **着地済みの列なら claim の記録も消す**（branch だけ消して記録を残すと二度と claim できない）
   - **取り下げの列では記録も branch も残す**。記録だけ消すと再 claim が同名 branch の衝突で落ちる
7. 人待ちの記録が `waiting` のままなら `cleared` にする（`wait-record.md` の例外行）。**渡しの記録と周回の記録が残っていれば同じ手順で消す**

- **存在確認だけで済ませない**。`積み残し・懸念` は 5 項目（何が / 影響範囲 / 放置すると / 判断材料 / 推奨）で書かれているので、そのまま応答へ出す
- **「対応不要」と書いてあっても落とさない**。それは書いた側の推奨であって、人の判断ではない
- **報告先を混ぜない**。応答に出し、Issue コメントは同内容なら追記しない
- **3 で止めたときは `cleared` にしない**。毎 tick 報告が出続けるのが正しい

**実体を消す直前に、worktree の dirty と `refs/stash` を見る**。

- **dirty なら片付けず報告する**
- **stash が残っていれば報告してから片付ける**。stash は worktree 削除では消えない。pop / drop しない

**片付けた後に `取り下げ` と読まれるのは正常**（終端の 2 値はどちらも上 3 つの action しか受けず、台帳は既に `完了`）。

経緯・報告のコメントは同内容が既にあれば追記しない。**例外は失敗の記録**で、同じコメントを upsert して `count` を伸ばす。

## 計画の失効

**action の 1 つ**（優先順の「計画の失効を伝える」）。1 tick に 1 つだけ実行して観測へ戻る。

- **届け先が居ないなら伝えない**。セッションが死んでいるときは「起こし直す」が先に実体を戻す
- **人待ち中と休止中は伝えない**。`cleared` になって `待機` に落ちた時点で、**枠を渡すより先に**伝える
- 「本文の変更」も同じ扱い。収束条件はその action の発火条件が偽になること（本文「1 tick」が SSOT）
- **再送を止める状態を記憶に持たない**。同じ内容の再送は害が無い（受け手は冪等に再 plan する）
- **繰り返しても更新されないままなら失敗として数える**（規則は本文「1 tick」）

**統合先が進んだら、稼働中セッションの計画と突き合わせる**（実装セッションは統合先を監視できない）。

**面ごとに「base から統合先まで」の変更 path を取り**、計画の `invalidationScope` か `resourceKeys` に交差したら、そのセッションに伝えて再 plan させる。**交差しなければ何もしない。**

**制御面だけで測らない**（同じ着地面へ別の課題が着地しても、制御面の default は動かない）。
