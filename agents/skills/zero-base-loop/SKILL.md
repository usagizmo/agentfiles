# ゼロベース突き合わせ

書いた diff を**ゼロベースで設計し直したときの姿**と突き合わせ、パッチ感・互換温存・規約違反を潰す。**判断主体は実行中のエージェント**（指摘は命令ではなく精査対象）。判定基準は `~/.agents/AGENTS.md` の設計原則。

**指摘が尽きるまで回す**（手順 5）。1 巡で切り上げない。

## 手順

### 1. スコープ

- 未コミットあり → working tree（`git diff` + `git diff --cached` + untracked）
- コミット済み feature ブランチ → `git diff <base>...HEAD`
- 迷い → ユーザー確認

### 2. プロンプト

作り方は `references/advisors.md`（ラウンドごとに新規で作る）:

```markdown
あなたはコードレビュアーです。コードは変更しないでください。

## 必読

- ~/.agents/AGENTS.md（設計原則）

## レビュー対象

次で変更を把握:
{未コミット: git status --short / git diff / git diff --cached / untracked の中身}
{base 比較: git diff <base>...HEAD}

## 観点

設計原則からの逸脱（ゼロベース一致・根本解決・互換 shim / deprecated / dead code の残存）。
加えて: バグ・エッジケース・軸の混在・SSOT 違反・規約違反

## 出力

重要度順「ファイル:行 / 問題 / 推奨修正」。なければ「指摘なし」のみ。nitpick 不要。
```

### 3. アドバイザーに渡す

`scripts/advisors.sh start <prompt-file>`。起動・回収と選び方は同ディレクトリの `references/advisors.md`。

### 4. 精査 → 修正

1 件ずつ: 実害か / 根本直しか / 採用・棄却・ユーザー相談。修正後はステップ 2〜4 を再実行。複数アドバイザーなら先に 1 本にマージし、出典タグ（`references/advisors.md` の出典表記）を付してから精査。

### 5. 打ち切り

指摘なし、または残指摘をすべて棄却できるまで。堂々巡りならユーザーに相談。

**「指摘なし」で打ち切れるのは、回収ヘッダが全員 `rc=0` の巡だけ**。欠落したまま指摘なしが来ても沈黙の証拠にはならない（見ていない目がある）。欠落は回収ヘッダの `rc≠0`。やり直すなら `start` から。指摘が出た巡は欠落のまま次へ進んでよい。

`start` が失敗して run dir が無いときは、アドバイザー無しで自分の判断だけを出す。

**指摘の深刻度・到達性が下がっても打ち切りではない**。実害と判断して直したなら、次の巡を回す。

報告: 修正 / 棄却 / 未解決（欠落アドバイザーがあれば併記）。
