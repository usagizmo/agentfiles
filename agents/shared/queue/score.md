# 譜面

人に読ませる面。自己完結のローカル HTML。作る skill が複数あるので、条件を 1 箇所に置く。

**SSOT にしない**。消える前提の面で、原本は必ず別にある（Issue 本文 / PR 本文 / skill・docs / 観測から作り直せる盤面）。

Issue / PR / コメントにパスも URL も書か**ない**。

**2 種ある**。**課題の譜面**（計画から着地まで、複数の工程が同じ 1 ファイルを書き直す）と、**単独の書き手が持つ譜面**（状況ボードのように、1 つの実行器だけが更新し続ける）。条件は共通で、引き当てだけが違う。

どの局面で作るかは各 skill が持つ。ここは満たすべき条件だけを定める。

## 置き場

`~/.local/state/agents/scores/`。`XDG_STATE_HOME` があるときは `$XDG_STATE_HOME/agents/scores/`。

| 種   | パス                                                 |
| ---- | ---------------------------------------------------- |
| 課題 | `<置き場>/<owner>/<repo>/<n>.html`                   |
| 単独 | `<置き場>/<固定名>.html`（状況ボードは `conductor`） |

- リポジトリの中に置か**ない**
- 自己完結させる。外部 CSS / 画像 / フォントを参照し**ない**（`file://` が壊れる）
- 書くたびにファイル全体を上書きする

## 条件

| 条件                                                                             | 外れたら                                                    |
| -------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| **中身は永続する場所にも残す**                                                   | 譜面が消えた時点で根拠ごと失われる                          |
| **残す先が無いなら作らない**。その場で消えてよい話か、Issue にすべき話のどちらか | 置き場の無いものが増え、どれが生きているか分からなくなる    |
| **1 課題につき 1 ファイル**。工程で割らない                                      | 同じ課題の面が 2 つ生え、人は古い方を開く                   |
| **判断だけを別ファイルに切り出さない**。根拠と結論、判断材料と計画で割らない     | 分かれた瞬間、片方しか読まれない                            |
| **引き当てはパス計算だけ**。Issue / PR を探さない                                | 会話は流れる。人待ちの記録は `cleared` で書き換わるので不可 |
| **その時点の SSOT から全体を書き直す。前の版を読み直さない**                     | 譜面が履歴の原本になる                                      |

## 作ったら開く

**書いたら、同じターンで path を開く**（macOS なら `open <path>`）。新規も更新も同じ。path を応答に貼るだけだと読まれずに流れる。

開けない環境では path を応答に書く。HTML を書くこと自体は省か**ない**。

## 課題の譜面

**課題（1 branch で着地する 1 まとまり）につき 1 ファイル**。工程をまたいで同じファイルを更新し続ける。

### 現在状態だけを載せる

譜面は原本の projection。書くたびに**そのときの SSOT から全体を作り直す**。

| 節               | 再生成元                                       |
| ---------------- | ---------------------------------------------- |
| 計画             | Issue 本文（契約の項目）                       |
| 実装計画         | 着手側の計画の記録（人が読む文の部分）         |
| 判断待ち         | 人待ちの記録の「いま待っている問い」           |
| 意図の確認       | 意図の確認の記録（見せたものと項目ごとの状況） |
| セッションまとめ | その回の事実（PR へコメントするのと同じ内容）  |

**履歴を積まない。失効した計画も残さない**。古い版が要るなら、それは Issue コメントか git の仕事。

### 出すことと、待つことは別

**譜面を出しても人待ちにはならない**。人待ちの記録を書くのは答えを待って応答を終えるときだけ（`wait-record.md`）。

逆に、待つなら記録が要る。同じ譜面に判断待ちの節を載せて応答を終えるなら、それは人待ち。

### 引き当て

`<置き場>/<owner>/<repo>/<n>.html` を計算する。無ければ新規に作る。

- `<owner>/<repo>` は課題がある repo（制御面）。着地面では**ない**
- `<n>` は Issue 番号。group は**代表の番号**（代表の決め方は `same-branch.md`）
- **Issue 番号を持たない課題はセッションをまたいで引き当てない**。`<置き場>/session/<そのセッションで決めた名前>.html` に書き、そのセッションの中で更新する

### group

group は 1 課題なので 1 ファイル。代表の番号で引く。成員の本文には書か**ない**。

## 単独の書き手が持つ譜面

**ファイル名を固定する**。外部化した URL の置き場は要らない。**数字だけのファイル名にしない**（課題の譜面と取り違えると、盤面が課題の面を上書きする）。

## 迷ったら作る

製品判断を伴わなくても作る。作らないでよいのは**残す先が無いときだけ**。
