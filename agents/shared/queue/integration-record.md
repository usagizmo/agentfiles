# 渡しの記録（merge の枠）

merge の枠を誰に渡したかを外部化したもの。merge は唯一の直列化点で常に 1 件しか進めないが、渡した相手は追随の push で `着地待ち` から外れるので、現在の状態からは「いま誰が着地してよいか」を復元できない。**この記録が権限の実体**で、状態は権限を表さない。

書くのも消すのも上位のキュー管理。**着地する側は読むだけ**で、自分では書かない・消さない。書く契機・消す契機・回収してよいかの判定は、キュー管理側の skill が SSOT。

````markdown
<!-- integration -->

```yaml
issues: [<Issue 番号>] # 対象集合の全番号
pr: <PR 番号> # 監査用。PR を使う着地面が無ければ書かない
```

<!-- /integration -->
````

同じ marker のコメントを複数作らない。**代表の Issue に 1 つ**（帰属は `same-branch.md`）。

**照合は `issues` で行う**。`pr` は監査用で、判定に使わない —— PR を作り直すと番号が変わるので、そこで照合すると自分に渡された枠を自分で失効させる。

**`pr` の欠落を壊れた記録にしない**。追加した PR 面がまだ PR を持たない段階でも記録は書ける。**PR を 1 つも使わない課題には、そもそも枠を渡さない**（merge が無いので直列化する対象が無い）。

**2 件以上あったら異常として報告する**。どちらが権限か決められないので、勝手に 1 つ選ばない。

## 渡す側

**書く → 書けたことを確かめる → 伝える**。この順序は落とせない。

1. 記録を upsert する
2. 取得し直して、`issues` が渡す相手の対象集合を指していることを確かめる
3. 確かめられてから伝える。**確かめられなければ伝えない** —— その tick は失敗として扱い、次の tick でやり直す（数え方はキュー管理側の skill）

2 を飛ばすと、書き込みが落ちたのに伝わった状態が残る。受け手は着地の直前に記録を確かめるので着地はしないが、伝えられた時点で各着地面の統合先への追随を始める —— その push で `着地待ち` から外れて候補集合を出るので、次の tick は記録がどこにも無いと読んで別の課題へ渡す。**渡された相手だけが、渡されたと信じたまま止まる。**

**伝わったかどうかは 2 の代わりにならない**。伝達の成否は受け手の実行器の話で、権限の所在は記録にしか無い。

## 着地する側

**着地の直前に、記録が自分の対象集合を指していることを確かめる**。指していなければ着地しない。

**枠を待つ variant にだけ効く**。人から 1 件を直接頼まれて単独で走る variant は枠を待たないので、記録の有無を着地の条件にしない（しないと、記録が存在しえないぶん永久に着地できない）。
