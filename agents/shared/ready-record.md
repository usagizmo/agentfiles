# 在庫の鮮度の記録

**計画済みへ進めるときに書き、着手されるまでのあいだ鮮度を持つ記録。**`refine` が書き、
`conductor` が読む。**書式と判定を別々の skill に置かない**（片方だけ直すと、書いた記録が
永久に不正と判定されるか、不正な記録が永久に通る）。

`resolve` が書く計画（`plan`）は claim 後にしか存在しないので、**在庫のあいだの鮮度を持つものが
他に無い。**記録が無いと、別の実装が着地して前提が崩れても誰も気づかず、claim してから
作り直すことになる（**そのときは既に容量 1 枠と write を握った後**）。

## 形式

````markdown
<!-- ready -->
```yaml
readySha: <計画時点の default の SHA>
issueDigest: <この Issue の本文のハッシュ>
invalidationScope:       # 変わると結論が崩れる範囲。空にしない
  - <path / 契約>
```
<!-- /ready -->
````

**ハッシュの取り方は `body-digest.md`**（`plan` と同じ規則。ここに書き写さない）。

同じ marker のコメントを複数作らない。更新するときは既存コメントを書き換える。

## 記録するのは自分の Issue 1 件だけ

**`plan` は対象集合の全件を持つが、`ready` は持たない。**単位が違う ——
`plan` は claim 後で group が確定し 1 セッションが全員を持つ。**`ready` は claim 前**で、
group の成員は 1 件ずつ別々に計画される。

ここで全件を書くと、**後から成員 B を計画して本文を更新した瞬間に、先に計画済みだった A が失効する。**
A は未計画へ戻り、また計画され、B を触るとまた戻る —— 収束しない。

group が揃っているかは既存の規則で足りる。陳腐化した成員は個別に未計画へ戻され、
**一部だけが計画済みの group は claim されない。**

## 書くときの順序

**この順でないと、自分の本文更新で即座に不一致になる。**

1. 本文を更新する
2. **更新後の本文を取り直して** digest を計算する
3. marker を upsert する
4. Status を計画済みへ進める

- **`invalidationScope` は空にできない。**空だと何にも交差せず、永久に失効しない
  （それでは記録を書いた意味が無い）。読んだ全ファイルではなく、**変わると結論が崩れる範囲**だけを書く。
  **広すぎ側の損失は作り直しの時間、狭すぎ側は検知漏れ**なので、迷ったら広く取る
- **`resourceKeys` / `expectedWrites` は書かない。**「どう作るか」は着手時に決まるので、
  ここでは書けない（書けないことは欠落ではない）
- **claim 後も消さない。**読むのは在庫のあいだだけと限定されている。消す操作を増やさず、
  差し戻しで計画済みへ戻ったときに鮮度情報が残る
- **他人の本文を触ったら、その Issue の記録も upsert する。**`Same branch as` の相互記載のように
  既に計画済みの Issue の本文を書き換えると、**相手の digest が合わなくなって陳腐化する**。
  書き換えた側がその場で digest を取り直せば、無関係な再計画を起こさずに済む。
  **触ってよいのは `issueDigest` だけ** —— `readySha` と `invalidationScope` は相手の計画結論に
  紐づく値で、自分の値へ差し替えると**相手の失効検知が別の範囲を見にいく**（陳腐化しないまま
  検知漏れになるので誰も気づかない）

## 読むときの判定

**読むのは `ledger` が `計画済み` かつ `progress` が `未着手` のときだけ。**それ以外の局面では
`plan` が鮮度を持つ。

次のいずれかなら**陳腐化**として未計画へ戻す。

- `readySha..default` の変更が `invalidationScope` に交差する
- `issueDigest` が現在の本文と一致しない
- 記録が無い

**判定できないものは陳腐化として扱う**（fail-closed）。個別の壊れ方を数え上げない —— block が
読めない、キーが欠けている、`readySha` が解決できない、`invalidationScope` が空か文字列の配列で
ないなど、**「交差を評価できない」はすべて同じ扱い**にする。列挙すると、次の壊れ方が漏れたときに
**永久に失効しない在庫**が残る。

戻すだけで、他には何もしない。在庫には branch も worktree も無いので片付ける実体が無く、
`ready` も消さない（次の `refine` が上書きする）。
