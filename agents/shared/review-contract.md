# レビュー委譲の契約

レビューを subagent に委ねるときの共通契約。誰が何をするかと、レビュアーのラベルに起因する親の扱いを定める。何を渡すか・指摘をどう分類するかは委譲元の skill が持つ。

| 誰         | すること                                                 |
| ---------- | -------------------------------------------------------- |
| レビュアー | 変更しない。指摘だけを重要度順で返す。nitpick は返さない |
| 親         | 指摘を再分類し、適用・検証・報告する                     |

- **レビュアーは判定して返す。**「〜も考えられます」ではなく、直すべきか否かを言い切る。判断材料が足りないなら、何が分かれば決まるかを書く。**親は「提案だった」を棄却の理由にしない**
- **レビュアーは「消してはいけないもの」も返す**。指摘だけを返すと、レビューは削る方向にしか働かない。**残す理由が本文に書かれていない不変条件は、次のレビューで消える**
- 依頼文に harness 固有の起動 API・agent 名を書かない。どの harness でも同じ依頼が通る形にする
- **subagent を持たない harness は自己レビューで代替する**。代替したときは理由を報告に明記する
