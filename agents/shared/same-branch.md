# `Same branch as #N`

Issue 本文に書く宣言。**「この課題は #N と 1 本のブランチで直す」**という意味を持つ。
気づいた側が、**関係する全 Issue の本文へ相互に書く。**

この宣言で結ばれた Issue の集合を **group** と呼ぶ。**group は推移的に閉じる** — A↔B と B↔C が
書かれていれば A・C も同じ group。相互記載が漏れていても、辿れる限りを 1 つとして扱う
（閉じないと 1 つの group が 2 本のブランチに割れる）。

## 書く条件

**片方だけ直すと、もう片方が同じ場所を二度触る**とき。テーマが近いだけでは書かない。

**書かないと決めたなら、本文に `Same branch as #N` の文字列を否定形で残さない。**group は本文の
文字列一致で辿るので、「`Same branch as #N` は書かない」と書くと**書いたのと同じに読まれる**。
片側だけが誤検出されると、相互記載の無い片肺 group として観測され、**存在しない group を揃えに
行く計画が起きる**。判断の理由を残すなら、番号を伴わない語（「同居宣言は書かない」）にする。

## 隣接する記法との違い

| 記法 | 意味 | 作業単位 |
| --- | --- | --- |
| `Same branch as #N` | **同居** — 1 本のブランチで一緒に直す | 同じ |
| `Depends on #N` | **順序** — #N を先に片付ける | 別 |
| `Refs #N` | 関連するだけ | 別 |

## 本文に書く理由

Issue 本文はセッションより先に存在する。だから着手する側は、**最初の 1 手で group 全体を
1 本として取れる。**

宣言が無いと、同じ場所を触るものが別々に着手され、並行した 2 本が rebase 衝突を作る。

## 共有するもの

group は **1 branch = 1 worktree = 1 セッション = 1 計画**で進む。**共有している成果物は
group の全 Issue に帰属する** — branch 名に入るのは代表番号だけなので、Issue ごとに引くと
非代表が永久に「何も無い」ように見える。

| 共有するもの | 帰属 | 書き先 |
| --- | --- | --- |
| remote branch / PR | 全員 | — |
| 固定 marker の記録（claim・計画・人待ち） | 全員 | **claim 後は代表の Issue に 1 つ**（復旧時に 1 回で読める）。**claim 前の人待ちは、渡された Issue に書く**（代表がまだ決まっておらず、2 人が同じコメントを書き換え合う） |
| worktree / セッション | 全員 | — |
| Status | **claim 時に全員を進行中にする**（代表だけだと、非代表を渡された側が「claim されていない」と読み、資源を待たずに着地まで走る） | — |

## どちらの集合を見るか

| 状況 | 見る集合 |
| --- | --- |
| **claim 済み**（記録がある） | **対象集合**（記録の `members`）。正規化・選出・資源はすべてこれ |
| **未 claim** | group（本文の `Same branch as` の推移閉包）。claim してよいかの判定に使う |

**group の `Depends on` は成員の和集合。**1 人でも未解決なら group ごと待つ —— 1 branch で
一緒に直すので、片方だけ先に着手できない。選出のフィルタも在庫の除外も同じ集合で引く。

## 代表

**最小番号。ただし claim した時点で固定する。**毎回本文から引き直すと、後から小さい番号が
`Same branch as` に加わったときに代表が変わり、**既にある branch を見失う**。
**claim 済みなら、記録の `representative` が代表**（引き直さない）。

**本文にだけ足された番号は次の着地まで別扱い。**台帳が揃っていないので共有成果物を継承させない。
加入させれば対象集合に入り、本隊と同じ `progress` になる（下記）。

## 対象集合

**対象集合は claim の記録が定める。**Status や assignee から推し量らない — 更新が両方失敗した
成員は集合から消えてしまい、**誰も直しに来なくなる**（集合の外なので不足を検知できない）。
逆に、人が自分で担当に付けただけの Issue を誤って引き込む。

branch を作った直後に、代表の Issue へ固定 marker で記録する。

````markdown
<!-- claim -->
```yaml
representative: <代表の Issue 番号>
members: [<Issue 番号>]   # 代表を含む全員
```
<!-- /claim -->
````

**Status と assignee は台帳であって集合の定義ではない。**記録にあるのに揃っていない成員は、
「揃えるべきもの」として埋める対象になる。

**本文の `Same branch as` に後から足されただけの番号は含まれない**（記録に無いため）。

**後から気づいて同じブランチで直したものは、加入させてから足す。**

1. Issue 契約が揃っているか確認する（欠けていれば加入させない）
2. **claim の記録の `members` に番号を足す**（これで対象集合に入る）
3. Status を進行中にし、assignee を揃える
4. 計画の `alsoResolves` に番号を足す

**2 が加入の実体。**3 と 4 が途中で落ちても、記録にあれば「揃えるべきもの」として埋められる。

**記録が無いとき（人が直接渡したセッション）は、本文へ `Same branch as` を相互に書くのが加入。**
資源も台帳も使わないので、それで足りる。

## 実体を触るとき

**単位は group、1 回だけ。**片付け・起こし直し・資源の受け渡し・branch の削除は、**代表の番号で
1 回**行う。Issue ごとに走らせると、同じ実体を別の成員が壊す — 非代表から起こすと
そちらの名前でセッションが生え、**孤児が増え続ける**。

**消すのは全員が終端のときだけ。**1 件だけ閉じた group で片付けると、まだ実装中の成員の
worktree ごと消える。**終端が混ざっている group は、判断を人へ返す。**
